# MNEME アーキテクチャ設計書

**Memory-Native Efficient Model** — トークナイザーフリー・外部完全記憶型の特化知能アーキテクチャ

## 1. 課題認識

### 1.1 トークナイザーは特化 AI にとって二重に非効率

現行 LLM の BPE / SentencePiece トークナイザーは「汎用 Web テキストの頻度統計」で語彙を固定する。特化タスクにとってこれは次の非効率を生む。

| 非効率 | 内容 |
|---|---|
| 語彙の死荷重 | 数万〜数十万エントリの埋め込み表(パラメータの数%〜十数%)のうち、特化ドメインで実際に使うのはごく一部。残りは推論のたびにメモリを占有するだけの死荷重になる |
| 分布ミスマッチ | 化学式・型番・コード・DNA 配列・日本語の複合語など、汎用コーパスに少ない系列は 1 文字単位に砕かれ、系列長が数倍に膨張して O(L²) の注意計算を直撃する |
| 境界の恣意性 | トークン境界は意味境界と無関係に頻度で決まる。数値の桁計算やスペル操作が不得意な一因 |
| 再適応の困難 | 語彙はモデルと癒着しており、ドメインが変わっても再学習なしには変えられない |

### 1.2 パラメータに知識を焼き込むのは記憶装置として最悪に近い

LLM は知識を重み(パラメータ)に勾配学習で焼き込む。これは記憶装置として見ると:

- **書き込みコストが膨大**: 事実 1 件の追加にも勾配計算・破滅的忘却対策が必要
- **不正確**: 想起は近似的で、ハルシネーションとして現れる
- **容量効率が悪い**: 記憶容量を増やす唯一の方法が「全パラメータの増加」であり、推論コストも連動して増える
- **編集不能**: 特定の知識だけを消す・直すことが原理的に難しい

### 1.3 仮説

> **賢い(=汎用的な処理能力を持つ)小さな知能コアと、圧倒的に正確で大量の外部記憶を分離すれば、はるかに少ない計算資源で複雑な特化タスクをこなせる。**

計算機の歴史のアナロジーで言えば、現行 LLM は「全データを CPU レジスタに置く設計」であり、MNEME は「小さな CPU + 大きな RAM/ディスク」の設計である。

## 2. 設計原理

MNEME は 3 つの原理からなる。

```
生バイト列
  │
  ▼
[1] エントロピー動的パッチング   … トークナイザーの置き換え(語彙表ゼロ)
  │    極小バイト LM が次バイト予測エントロピーを推定し、
  │    情報量が跳ねる位置でパッチを区切る
  ▼
[2] 小さな知能コア               … パッチ潜在列上の因果 Transformer
  │    知識を持たず「処理」に徹する。系列長はバイト列の 1/6 程度
  ▼
[3] 外部エピソード記憶           … 知識の置き場所
       (key, value) 潜在ベクトルの完全検索ストア。
       書き込みは append のみ(勾配ゼロ)、読み出しは top-k 完全検索
  ▼
バイト列を自己回帰復号
```

### 2.1 原理 1: トークナイザーの廃止(エントロピー動的パッチング)

- 入出力は **生バイト(0–255)+ 特殊 3 記号のみ**。語彙構築・OOV・正規化が消滅する。
- 極小のバイトレベル LM(本プロトタイプでは約 5 万パラメータの GRU)が各位置の次バイト予測エントロピー H(bᵢ | b<ᵢ) を推定する。
- H が閾値 θ を超えた位置(=予測が難しい、情報が跳ねる位置)でパッチを区切る。予測が容易な区間(単語の続き、定型句)は長いパッチに自然に圧縮される。
- 閾値 θ は目標平均パッチ長からコーパスの分位点で校正する(`EntropyPatcher.calibrate`)。
- **特化への再適応はエントロピーモデル(5 万パラメータ)の差し替えだけ**で済む。本体は再学習不要。

これは Byte Latent Transformer(Pagnoni et al., 2024)のエントロピーパッチングの考え方に基づく。BLT はこの方式で「トークナイザーベースと同等の性能をより少ない推論 FLOPs で」達成できることを 8B 規模まで実証しており、本設計の実現可能性の根拠となる。

### 2.2 原理 2: 知能と記憶の分離

知能コア(パッチ潜在列上の因果 Transformer)は**知識を持たない**。学習するのは:

- バイト列 ⇄ 潜在ベクトルの可逆な符号化・復号(汎用スキル)
- 文脈の統合と、記憶から引いた情報の利用(汎用スキル)

事実・ドメイン知識はすべて外部記憶に置く。これにより:

- コアのパラメータ数はタスクの**複雑さ**にのみ比例し、知識の**量**からは独立する
- 知識量が 64 件でも 100 万件でも、コアの推論コストは(top-k 検索コストを除き)一定

### 2.3 原理 3: 外部エピソード記憶(完全・追記型・編集可能)

`EpisodicMemory` は (key, value) 潜在ベクトル対のストアで:

- **書き込み**: append のみ。勾配計算ゼロ。事実 1 件の追加は 1 回のエンコードのみ
- **読み出し**: コサイン類似度 top-k の**完全検索**。近似的な「重みからの想起」と違い、書いたものは正確にそのまま返る
- **編集**: エントリ単位で削除・上書き・差し替えが可能(監査可能性・忘却権にも対応できる)
- **特化の切り替え**: 記憶ストアを差し替えるだけでドメインが変わる

知能コアへの統合は Memorizing Transformers(Wu et al., 2022)と同型のゲート付き読み出し層(`MemoryAttention`)で行う: `h ← h + σ(gate([h; r])) ⊙ Wr`(r は top-k 検索結果の類似度加重和)。

## 3. プロトタイプ実装

| モジュール | ファイル | 役割 |
|---|---|---|
| `EntropyPatcher` | `patcher.py` | 極小バイト LM によるエントロピー推定と動的パッチ分割 |
| `ByteEncoder` / `ByteDecoder` | `modules.py` | バイト列 ⇄ 潜在ベクトルの符号化・復号(GRU) |
| `EpisodicMemory` | `memory.py` | 外部 (key, value) 完全記憶ストア |
| `MemoryAttention` | `lm.py` | 記憶からのゲート付き読み出し層 |
| `MnemeLM` | `lm.py` | 全結合: パッチング → 潜在コア → 記憶読み出し → バイト復号 |
| `MemoryRecallModel` / `ParametricRecallModel` | `recall.py` | 検証実験用の外部記憶モデルとパラメータ記憶ベースライン |

プロトタイプでは局所符号化に GRU を用いた(CPU で高速・実装が単純)。スケール時は BLT 同様の軽量 Transformer + クロスアテンションに置き換える想定。

## 4. 検証実験

### 4.1 実験 1: 知識想起 — 外部記憶 vs パラメータ記憶

ランダムな key(8 文字)→ value(6 文字)の事実集合を N 件保持し、完全一致で想起できるかを測る。両モデルは同一の符号化・復号ネットワーク規模。

- **MNEME**: 汎用コーデック(文字列⇄潜在の可逆写像)を**事実を一切見せずに**一度だけ学習。事実は外部記憶に書き込むのみ(**事実あたり勾配ステップ 0**)
- **ベースライン**: 事実集合そのものを end-to-end 勾配学習で重みに焼き込む(通常の LLM の知識保持の縮図)

結果は `README.md` の実験結果表を参照。要点:

1. MNEME は事実数 N によらずほぼ完全な想起を維持する(検索は完全一致 top-1、復号誤りのみが上限)
2. ベースラインは N の増加とともに固定学習予算では焼き込みきれず精度が崩壊する
3. MNEME の知識追加コストはエンコード 1 回(ミリ秒)、ベースラインは全再学習(分)
4. 学習に一度も出てこなかった新事実も、書き込むだけで即座に想起できる(知識編集)

### 4.2 実験 2: エントロピー動的パッチング

極小バイト LM を小コーパスで学習し、パッチ境界を可視化する。予測が容易な区間は長く圧縮され、単語頭や分布外の系列では細かく切れることを確認する(`experiments/run_patcher_demo.py`)。潜在系列長はバイト列の約 1/6 になり、コアの O(L²) 計算が約 1/36 に落ちる。

## 5. 関連研究(設計の根拠)

| 研究 | 本設計への示唆 |
|---|---|
| Byte Latent Transformer (Pagnoni et al., 2024) | エントロピーパッチングでトークナイザーフリーが 8B 規模で BPE と同等以上・推論 FLOPs 削減を実証 |
| MegaByte (Yu et al., 2023) | 固定長パッチでのバイトレベル階層モデル。可変長パッチはその改良 |
| kNN-LM (Khandelwal et al., 2020) | 外部データストアの補間だけで LM の困惑度が改善。記憶の外部化の原型 |
| RETRO (Borgeaud et al., 2022) | 検索拡張により 25 分の 1 のパラメータで GPT-3 級の性能。 「小さいコア + 大きい記憶」のスケール実証 |
| Memorizing Transformers (Wu et al., 2022) | kNN 記憶へのゲート付きアテンション。本実装の `MemoryAttention` の直接の原型 |
| Physics of LLMs Part 3.3 (Allen-Zhu & Li, 2024) | パラメータ記憶の容量は約 2 bit/param が上限。外部化の定量的動機 |

## 6. 限界と今後の課題

- **プロトタイプの規模**: 本実装は数十万パラメータ・合成タスクでの原理検証であり、実タスクでの実証は今後の課題
- **検索のスケール**: 現在は総当たり top-k。数億エントリ規模では FAISS 等の近似最近傍(積量子化 + HNSW)に置き換える(精度と引き換えの近似だが recall@k は 0.99 以上に保てる)
- **多段推論**: 記憶を複数回引きながら推論する(read → think → read)ループはコアの学習タスク設計が必要
- **書き込み方策**: 何を記憶に書くか(全部か、驚き=高エントロピーのものだけか)の方策学習
- **エントロピーモデルとコアの結合学習**: 現在は分離学習。境界の勾配を通す(straight-through)ことで end-to-end 化できる可能性

## 7. 結論

トークナイザーと知識のパラメータ焼き込みは、どちらも「汎用 Web テキストの統計を巨大な固定構造に固める」という同じ設計思想の産物であり、特化 AI にはどちらも不要である。バイトから直接学び、知識は正確な外部記憶に置き、小さなコアは処理に徹する — この分業により、**知識量と計算コストを切り離し、再学習なしで知識を編集・拡張できる特化知能**が構成できることをプロトタイプで確認した。
